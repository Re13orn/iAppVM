# 单 App 网络与代理

在所选目标工作台打开「网络捕获与代理 → 设置捕获与代理」。HTTP CONNECT / SOCKS5 为当前支持的无认证代理；按手机可访问的服务器地址和端口填写。手机 `127.0.0.1` 是手机自身；USB 的 Gadget 转发端口与 HTTP/SOCKS 代理端口完全不同。

## 一次正确验证

1. 测试当前输入的代理地址；它只验证草稿，不保存配置。
2. 保存，关闭目标窗口并重新启动。
3. 检查“目标运行配置”是否匹配本次 PID、启动时间和保存配置的 SHA-256；待重启、历史回执不能算已生效。
4. 用一个已知且获准测试的 App 请求验证代理端观察与手机 Socket 隧道/错误数。是否可见 HTTP 明文或 TLS 业务内容再单独检查。

代理测试固定执行到 `example.com:443` 的 HTTP CONNECT 或 SOCKS5 握手，不发目标 App 的业务请求。握手通过不证明 TLS 信任、证书固定处理、实际业务成功或全流量覆盖。407 表示要求认证，当前无认证配置不能解决；拒绝/超时/主机不可达需分别检查代理监听、地址、防火墙和路径。

本地网络访问需要手机与代理所在电脑的网络可达，并允许 iAppVM 本地网络访问。同一 Wi-Fi 与权限已允许仍不保证端口可达，进一步检查访客网络隔离、电脑代理是否仅监听 127.0.0.1 等。不要反复要求用户确认已经确认的设置，也不要无依据关闭防火墙或修改系统代理。

## 捕获和代理是两条链路

内置请求捕获主要观察已支持的 URLSession 等 API。原生 Socket、Flutter/Dart、自建网络栈、特殊 Network/WebKit 上下文等可能绕过某一层观察点。Socket 中继成功不等于 HTTP 请求正文能在 App 内显示。

当前实现为受支持的 URLSession/WebKit/默认 Network 上下文设置代理，并对目标映像的部分 Socket connect 路径做 HTTP CONNECT/SOCKS5 中继。并非设备 VPN 或系统级全流量捕获；不能保证每条自定义连接都被覆盖。拦截到的外部 UDP 路径会拒绝以防直连，但不据此声称全部 UDP 都已捕获。受配置控制的代理失败连接不回退直连，也不把“设置了代理”当作所有连接都已受控的证明。

HTTPS 保持原有证书校验。仅设置 CONNECT/SOCKS 代理不会解除证书固定或自动解密 TLS。用户要求相关测试时，按实际网络栈和授权范围另作方案，别直接把异常归因于代理功能失效。

如果只看到 Sentry：它只证明 Sentry 对应的路径被当前观察点看到。确认是否触发了实际业务、该业务用什么网络栈、代理端是否看到 CONNECT/TCP，再判断是捕获缺口、代理路径缺口还是 TLS/业务失败。不要声称“只支持 Sentry”，也不要声称所有业务 HTTPS 都已成功代理。

正文捕获单独启用；没有必要时保持关闭。选择正确数据容器和捕获会话，只查看诊断所需请求，分享日志前检查敏感内容。
