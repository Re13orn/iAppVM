# App、脚本与容器操作

以下入口适用于提供相应工作台功能的版本。以实际界面为准；不要求用户持有开发源码。

## 导入与启动

通过 App 页的导入入口选择获准测试的 IPA。目标需要适合当前架构且可用于重签名；App Store 加密包不能仅靠导入自动变成可分析的解密包。导入流程会尝试准备 Gadget，但不保证每个 App 都能注入或运行；32 位、禁止 TweakLoader、签名/entitlements 或完整性检测等情况需分别诊断。

在目标的工作台检查「Frida 调试」，需要时使用「启用 Frida 调试」或「更新调试配置」。后者用于旧配置和共享插件目录的专属化。按提示完成手机签名；手机证书未配置时才走当前配置支持的签名流程，不默认让电脑反复重签。

通过独立测试窗口启动目标，保留管理页用于调试。设置改变后通常要完全关闭目标窗口再启动；仅切回前台不等于重新启动。App 的显示名、导入目录名、原始 bundle ID、数据容器 UUID 是不同标识，不能混用。

## 启动前自检与配置预设

提供这些功能的版本可从目标工作台进入「启动前自检」与「测试配置预设」。启动时遇到已知阻断项会暂停并指向签名、脚本、容器、网络等对应入口；普通提示不等于阻断。已有匹配手机证书时，待签名配置可在启动时自动处理；描述文件到期信息和签名记录仍不代表运行时验签。

关闭目标后，将当前 Gadget 版本、脚本组合/自动模式、控制台选项、代理/捕获和所选数据容器保存为命名预设。应用前核对内容，按提示签名并重新启动。可重命名、用当前配置更新或删除；删除不改变当前配置和数据。最近应用标记会区分当前字段匹配与已改变。

预设保存引用，不复制脚本内容或沙盒。脚本库内编辑仍会影响引用它的预设；引用被删除时先重新选择并保存。预设目前适用于本地 App，运行中或签名任务未结束时不可切换。不同 Gadget 能力、代理覆盖和业务兼容性仍需实际验证。

配置切换使用独立插件目录及可恢复的配置事务；遇到未完成切换时先关闭目标，在自检页恢复。若配置之后被其他操作修改，自动恢复会停止，不擅自覆盖。恢复不回滚业务数据。不要手动删除整个配置目录来解除提示。

## 手机自动脚本：无需电脑

1. 「模块 → Frida 脚本库」导入 UTF-8 `.js`，或新建/编辑脚本；也可从「Frida 调试 → 启动脚本 → 管理全局脚本库」进入。
2. 关闭目标，在「启动脚本」选中一个或多个 JS，开启「启动时自动运行脚本」并保存。按当前页面提示完成必要签名。
3. 重新启动目标，在「调试日志」选择本次启动会话，先确认诊断脚本的 `[iAppVM]` 输出，再验证实际 Hook。

以下限制描述支持多脚本工作台的实现，其他版本按页面提示核实。每个导入实例有独立配置归属；共享全局脚本库不等于所有 App 都启用这些脚本。UUID 区分同名脚本，单个最多 8 MiB；每 App 最多 32 个、合计 32 MiB。自动脚本实际使用私有快照，源代码不拼接、不改写；各自独立 JS 上下文，不共享全局变量，也不保证跨脚本异步初始化顺序。有依赖时先打包为一个脚本。

修改库内脚本在下次真正启动时刷新；没有热替换。删除仍被某 App 选中的脚本会阻止该 App 下次启动，先取消勾选或重新选择。编辑被多个 App 共用的同一脚本会影响这些 App 下一次启动，必要时复制成独立条目。

自动模式不开放电脑监听端口。要用电脑，关闭自动脚本、保存并重启目标，恢复该 App 原来的监听身份。

## 日志与状态

「Frida 调试」分别展示 Gadget 准备、签名记录、目标进程、Gadget 本次加载与电脑连接。已有签名记录不等于实时密码学验证；历史回执不等于当前运行。

「调试日志」可选目标控制台或配套电脑客户端日志。自动模式的 `console.log/warn/error` 经 stdout/stderr 记录；`send()` 需要消息接收方，纯自动模式先用 console 验证。运行会话控制台上限 4 MiB，保留最近 10 次，UI 显示末尾 256 KiB，可分享完整受限文件。

只有配套客户端主动回传心跳：约每 2 秒，8 秒后过期，匹配 PID 与本次启动时间；普通 CLI 不回传。因此“电脑连接未确认”不必然是失败。目标运行与授权页中的“running”表示窗口已经建立，不代表业务完成或所有插件已成功加载。

## Gadget 版本

「Gadget 版本」列出当前安装包内置和已保存的版本，实际版本号以页面为准；提供「从 GitHub 按需下载」的版本可使用官方预置入口、刷新近期稳定发布或手动输入版本号。资源来自 frida/frida 官方 Release，下载时验证大小、SHA-256，自动 XZ 解压与 iOS arm64 检查；新版本用上游 digest，历史预置版本有固定校验值。其他没有校验值的历史版本使用手动导入。

手动导入选择解压后的 iOS Gadget `.dylib`，支持 Universal 普通 arm64 分片；不能把 arm64e-only、Android .so 或 frida-server 当 Gadget 导入。手动输入的版本号是用户标注，并非执行二进制识别的结果。

下载/导入仅加入全局版本库。关闭目标后，返回版本页选择「应用并重新签名」，重启目标；不同 App 可分别选择。切换保留旧插件目录。电脑 Python `frida` 与实际 Gadget 使用完全相同版本；`frida-tools` 是独立版本体系，不能把它的版本号设成 Gadget 版本。

GitHub 请求可能超时或限流；按页面实际错误取消、重试，或在电脑下载官方资源后手动导入，不默认换镜像或修改系统网络。不要把某台设备曾经成功或超时的记录当作其他用户的测试结论。Gadget 版本的应用/Hook 兼容性要分别验证。

## 沙盒与进程授权

在目标工作台选择「浏览沙盒」，确认顶部 App 与选中容器，首次启动后才可能有数据容器。文件操作/导出范围是所选导入实例；程序包、插件目录和数据目录不同，不把代码缓存当业务数据源。

「运行状态与授权」用于查看本次独立窗口的进程、容器与受限文件授权，以及关闭对应窗口；它不授予任意系统文件访问能力，也不会把目标变成越狱进程。PID 会重用，核对本次启动记录后再停止目标。

遇到“没有访问许可”：记录操作、路径类别与错误；检查是否旧配置目录、只读导入源、目标正在运行或文件已被替换。优先 UI 的更新专属配置/当前托管存储流程；不递归 chmod/chown、不删除原始 IPA 或整个 Documents 来试错。显示路径时可以指出内部 `iOSVM` 名称是兼容设计。
